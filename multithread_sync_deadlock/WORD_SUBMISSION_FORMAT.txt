4. THREADING MODELS EXPLAINED
=============================================================================

USER-LEVEL THREADS:
- Managed by user-space libraries
- Fast context switching
- No kernel involvement
- Example: Python threads (GIL affected)

KERNEL-LEVEL THREADS:
- Managed by operating system
- True parallelism on multicore
- Higher overhead
- Examples: Windows threads, Linux pthreads

HYBRID MODEL:
- M:N mapping (M user threads to N kernel threads)
- Balances performance and functionality
- Complex implementation

MULTITHREADING MODELS:
- Many-to-One: Multiple user → single kernel thread
- One-to-One: Direct mapping, true parallelism  
- Many-to-Many: Flexible mapping, best performance

=============================================================================
5. THREADING BENEFITS
=============================================================================

RESPONSIVENESS:
- Non-blocking user interfaces
- Background task execution
- Better user experience

RESOURCE SHARING:
- Shared memory space
- Efficient data communication
- Lower overhead than processes

CONCURRENCY:
- Simultaneous task progress
- Better resource utilization
- Improved system throughput

PARALLELISM:
- Multi-core utilization
- True parallel execution
- Significant speedup potential

=============================================================================
6. THREADING CHALLENGES
=============================================================================

RACE CONDITIONS:
- Concurrent access to shared data
- Unpredictable results
- Solution: Locks, semaphores

DEADLOCKS:
- Circular waiting for resources
- System becomes unresponsive
- Solution: Proper lock ordering

OVERHEAD:
- Context switching costs
- Thread management overhead
- Synchronization penalties

PYTHON GIL:
- Prevents true CPU parallelism
- Only one thread executes bytecode
- Better for I/O-bound tasks
